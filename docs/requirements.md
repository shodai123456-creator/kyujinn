# 要件定義書

## 1. 目的

複数の適法な求人情報源から求人を集約し、ユーザーの経歴・希望条件との適合度を定量評価する。求人探索の見落としと比較コストを減らし、iPhoneから保存・除外・応募管理まで完結できる状態を作る。

## 2. 対象ユーザー

- MVP：単一ユーザーによる個人利用
- 将来：複数ユーザーに一般公開

MVPの単一ユーザー前提をコードに埋め込まず、主要データには最初から `user_id` を持たせる。

## 3. 確定条件

- 居住地：神奈川県を維持する
- 通勤基準駅：茅ヶ崎駅
- 許容通勤時間：片道150分以内
- 職種、業界、雇用形態、勤務地、リモート希望：設定画面で複数選択可能
- 評価項目と重み：ユーザーが変更可能
- 履歴書入力：PDF、DOCXの両方に対応
- 費用：初期運用は完全無料
- 通知：毎朝のまとめ通知、高得点求人の即時通知
- 端末：iPhoneを主対象とし、PCブラウザにも対応

## 4. MVPの機能要件

### FR-01 プロフィール

- PDFまたはDOCXの履歴書・職務経歴書を読み込める
- ファイルはブラウザ内で解析し、原本をサーバーへ送信しない
- 氏名、住所、電話番号、メール等は保存前に除外できる
- 抽出した職歴、職種、スキル、資格、経験年数を編集できる
- スキャンPDFはブラウザ内OCRで補助し、抽出結果を必ず確認させる

### FR-02 希望条件

- 職種、業界、雇用形態を複数選択できる
- 最低年収、希望年収、勤務地、リモート頻度、転勤可否を設定できる
- 必須条件、希望条件、除外条件を区別できる
- 評価軸の重みを合計100%になるよう調整できる

### FR-03 求人取得

- 許可済みの公式API、RSS/Atom、企業採用ページ、公開ATSフィードから取得できる
- URL、求人本文、PDF、画像をユーザー操作で取り込める
- 取得元、原文URL、取得日時、掲載日時を保持する
- 同一企業・職種・勤務地・本文指紋を使って重複を統合する
- 掲載終了または長期間更新されない求人を非表示化できる

### FR-04 推薦評価

- 求人ごとに0〜100点を算出する
- 評価内訳、加点理由、減点理由、情報不足を表示する
- 点数とは別に評価確度を「高・中・低」で表示する
- 必須条件に明確に反する求人は「対象外」とする
- ユーザーの保存・除外・応募結果を、将来の重み調整候補として記録する

### FR-05 通勤判定

- 茅ヶ崎駅を出発駅として扱う
- 通勤時間が確認済みで150分を超える求人は対象外にする
- 求人に最寄り駅がない場合は勤務地住所を保持する
- 無料で信頼できる公共交通経路APIがないMVPでは、経路検索へのリンクと手入力確認を提供する
- 未確認の通勤時間を推測だけで対象外にしない
- 未確認求人は「通勤要確認」とし、評価確度を下げる

### FR-06 求人管理

- 新着、保存、除外、応募予定、応募済み、面接中、内定、辞退を管理できる
- メモ、応募日、次回アクション日を登録できる
- 同じ求人を再取得しても状態とメモを失わない

### FR-07 通知

- 毎朝7時に上位求人をまとめて通知する
- 新着求人を1時間ごとに確認する
- 初期値80点以上の新着を即時通知する
- 通知時刻、即時通知閾値、通知種別を変更できる
- 同一求人を重複通知しない

### FR-08 認証とプライバシー

- MVPでもインターネット公開面に認証を必須とする
- パスワードを平文保存しない
- 履歴書原本をクラウド保存しない
- 構造化プロフィールの保存前にユーザーへ内容を見せる
- データのエクスポートと削除を提供する

## 5. 求人取得コンプライアンス

### 自動取得を許可する条件

次をすべて満たすソースだけを自動取得対象とする。

1. 公開情報であり、認証突破を必要としない
2. 利用規約で禁止されていない、または公式API・フィードとして許可されている
3. robots.txtで対象パスが拒否されていない
4. CAPTCHA、レート制限、アクセス制御を回避しない
5. 取得頻度を低く保ち、明示されたレート制限を優先する
6. 一般公開時に必要な転載・再表示条件を満たせる

### 禁止する実装

- Indeed、Wantedly等の禁止規定があるサイトへの無許可スクレイピング
- ログイン済みセッションやCookieを使った自動巡回
- CAPTCHA回避、IPローテーション、偽装User-Agent
- サイト本文の無断再配布
- 応募操作の自動化

### コネクタ審査

各コネクタに以下を記録し、確認できないものは既定で無効にする。

- 利用規約URLと確認日
- robots.txt確認結果
- API・フィード仕様
- 許可される保存項目と表示範囲
- 最小アクセス間隔
- 個人利用限定か一般公開可能か
- 最終審査者と判定理由

## 6. 推薦ロジック

### 必須条件

- 神奈川県に居住し続けられる
- 確認済み通勤時間が片道150分以内
- ユーザーが指定した必須雇用形態・勤務地・転勤条件を満たす

不明な条件は即時除外せず「要確認」とする。

### 初期重み

| 評価軸 | 初期値 |
| --- | ---: |
| 経験・スキル適合 | 25% |
| 給与 | 20% |
| 仕事内容 | 20% |
| 働き方 | 15% |
| 成長性 | 10% |
| 企業安定性 | 10% |

通勤は基本的に必須条件として扱い、通勤利便性を加点軸にするかは設定可能にする。

### 点数と確度

`総合点 = Σ(各評価軸の0〜100点 × ユーザー重み)`

評価確度は、給与、勤務地、仕事内容、必須スキル等の重要項目がどれだけ埋まっているかで算出する。高得点でも確度が低い求人は即時通知対象から除外できる。

## 7. 非機能要件

- iPhone Safariおよびホーム画面PWAで主要操作ができる
- 通常画面の主要API応答は目標2秒以内
- 同一収集処理を再実行しても重複登録しない
- コネクタ単位で停止できる
- 日次バックアップまたはエクスポートを可能にする
- 無料枠超過時は課金せず、処理停止と警告を優先する
- ログに履歴書本文、認証情報、個人情報を出力しない

## 8. MVP対象外

- 求人への自動応募
- 面接日程の自動調整
- 有料生成AIによるキャリア相談
- 求人サイトのログイン代行
- 正確な全国公共交通ルート計算
- App Store配布のネイティブiOSアプリ
- 企業口コミサイトの無許可収集

## 9. MVP受入条件

1. PDFとDOCXからプロフィール候補を抽出・修正・保存できる
2. 許可済みソースと手動取込から求人を登録できる
3. 重複求人が統合される
4. おすすめ点、内訳、理由、確度が表示される
5. 茅ヶ崎駅から150分超と確認された求人が対象外になる
6. 保存・除外・応募状態が再取得後も維持される
7. iPhoneのホーム画面から利用できる
8. 毎朝通知と高得点通知を重複なく受け取れる
9. 履歴書原本がサーバーに送信・保存されないことをテストで確認できる
10. 禁止サイトへの自動アクセスが存在しないことをコネクタ一覧で確認できる
