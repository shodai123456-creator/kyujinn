# 基本アーキテクチャ

## 1. 採用構成

| 層 | 技術候補 | 役割 |
| --- | --- | --- |
| PWA | TypeScript + Vite | iPhone向けUI、オフライン骨格、履歴書の端末内解析 |
| API | Cloudflare Workers | 認証、求人・設定・状態管理、通知登録 |
| DB | Cloudflare D1 | 構造化プロフィール、求人、スコア、応募状態 |
| 定期処理 | Workers Cron Triggers | 収集、再評価、朝通知、即時通知 |
| Push | Web Push + VAPID | iPhoneホーム画面PWAへの通知 |
| ローカル開発 | Wrangler + Miniflare互換環境 | 無料での開発・テスト |

有料AI APIは利用しない。無料枠の上限に達した場合、自動的に有料プランへ移行せず処理を停止する運用とする。

## 2. プライバシー境界

### ブラウザ内だけで扱うもの

- PDF・DOCXの原本
- 原本から除外前の氏名、住所、電話、メール
- OCR途中データ

### 明示確認後にクラウド保存するもの

- 匿名化済み職歴
- スキル、資格、経験年数
- 希望条件と評価重み
- 求人状態、メモ、通知設定

## 3. 求人収集パイプライン

1. Cronまたはユーザー操作でコネクタを起動
2. コネクタポリシーが `approved` であることを確認
3. ETag、Last-Modified、取得間隔を確認
4. API・フィード・許可済み公開ページを取得
5. 求人項目を共通形式へ正規化
6. URL、外部ID、本文指紋で重複判定
7. 新規・変更求人だけを保存
8. 必須条件と推薦点を再計算
9. 閾値を超えた新着だけを通知キューへ登録

## 4. 手動取込

- URLと本文の貼り付け
- PDF・画像のブラウザ内解析
- 求人メール本文の貼り付けまたは `.eml` 取込
- 取込結果をユーザーが確認してから保存

URLだけから本文を自動取得する機能は、対象ドメインのコネクタが許可済みの場合だけ実行する。未承認ドメインでは本文貼り付けを求める。

## 5. 無料推薦エンジン

- 条件一致：年収、雇用形態、勤務地、リモート、転勤等の決定的ルール
- スキル一致：正規化辞書、同義語、経験年数、必須・歓迎の区別
- 文章一致：日本語トークン化後のBM25またはTF-IDF
- 説明生成：テンプレートによる根拠表示
- 学習補助：保存・除外理由から重み変更候補を提示し、変更はユーザー承認制

生成AIがなくても、同じ入力に同じ結果を返し、点数の根拠を追跡できることを優先する。

## 6. 通勤判定

MVPでは有料交通APIを使用しない。求人の最寄り駅または勤務地を表示し、茅ヶ崎駅を出発地にした経路検索リンクを生成する。ユーザーが確認した片道時間を保存し、150分超を必須条件違反として扱う。

住所だけからの距離推測は参考値に留め、公共交通の所要時間として断定しない。

## 7. 認証

- MVP：単一ユーザーのPasskey認証と復旧キー
- セッション：短命な署名Cookie、Secure、HttpOnly、SameSite設定
- 将来：複数ユーザー、アカウント削除、データ分離を追加
- APIの全クエリで `user_id` を必須条件にする

## 8. ディレクトリ案

```text
job-match-app/
  apps/
    web/                 # PWA
    worker/              # API・Cron・Push
  packages/
    shared/              # 型、バリデーション、評価式
    resume-parser/       # ブラウザ内PDF・DOCX解析
    scoring/             # 推薦ロジック
    connectors/          # 許可済み求人コネクタ
  migrations/            # D1 SQL
  tests/
    fixtures/
    integration/
  docs/
```

## 9. 障害時の方針

- 求人ソース障害：他コネクタと画面利用を継続
- 規約変更：対象コネクタを即時停止できるfeature flagを持つ
- 無料枠超過：収集頻度を落とし、課金せず管理画面へ警告
- Push失敗：次回起動時に未読通知として表示
- DB障害：D1の復旧機能と定期エクスポートを利用
